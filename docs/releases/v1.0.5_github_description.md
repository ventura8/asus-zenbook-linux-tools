# ASUS ZenBook Linux Tools v1.0.5 - LXQt Configure Privilege-Escalation Fix

**ASUS ZenBook Linux Tools v1.0.5** is a security release closing a local
privilege-escalation path in LXQt desktop configure, where root previously
followed a user-controlled symlink under `~/.config` while chmod'ing,
chown'ing, and writing shortcut state.

---

## 🛡️ LXQt configure privilege-escalation fix

* **Privilege drop before touching user paths**: `lib/install-lxqt.sh`
  `_lxqt_ensure_conf_dir` and `_lxqt_atomic_write_conf` now run `mkdir`,
  `chmod`, and the config write **as the target LXQt session user** via
  `_install_run_as_user` — the same pattern already used for GNOME extension
  installs — instead of as root.
* **Symlink rejection**: Explicit `[ -L ... ]` checks refuse to operate on
  `~/.config`, `~/.config/lxqt`, or `globalkeyshortcuts.conf` when any path is
  a symlink, as defense-in-depth.
* **Removed the vulnerable helper**: `_lxqt_chown_path` (root `chown` without
  `--no-dereference`) is no longer needed and has been removed.

**Impact**: an unprivileged local user with an active LXQt session could
previously replace `~/.config` with a symlink to a privileged directory (e.g.
`/etc`) before an administrator ran `sudo ./install.sh` or
`sudo asus-zenbook-configure` with the LXQt component, causing root's
`chmod`/`chown` to follow the symlink and hand that user ownership of the
privileged target. Configure now drops to the session user first, closing
the path.

## 🧪 Verification

* Mocked LXQt E2E suite (`tests/e2e/mock/test_install_de_lxqt.py`) passes
  unchanged against the hardened implementation.
* `bash -n` clean and `shellcheck` passing on `lib/install-lxqt.sh`, with only
  the pre-existing informational `SC2016` notices on intentionally
  single-quoted privilege-drop scripts.
* New coverage-driver regression cases fake root to exercise the
  `_install_run_as_user` root branches directly, proving symlinked
  `.config`/`lxqt`/conf destinations are rejected without touching the real
  target, and that normal writes still succeed.

## 📥 Installation

### Ubuntu PPA (resolute)

```bash
sudo add-apt-repository ppa:ventura8/asus-zenbook-linux-tools &&
  sudo apt update &&
  sudo apt install asus-zenbook-linux-tools
```

### GitHub Release packages

Download **`SHA256SUMS`** and your release asset from the
[v1.0.5 release assets](https://github.com/ventura8/asus-zenbook-linux-tools/releases/tag/v1.0.5),
then verify the downloaded asset before install:

```bash
grep -F 'your-asset-filename' SHA256SUMS | sha256sum -c -
```

| Asset | Install (after checksum verify) |
| --- | --- |
| `.deb` | `sudo apt install ./asus-zenbook-linux-tools_*.deb` |
| `.rpm` (Fedora/Rocky/Alma) | `sudo dnf install ./asus-zenbook-linux-tools-*.rpm` |
| `.rpm` (openSUSE) | `sudo zypper install --allow-unsigned-rpm ./asus-zenbook-linux-tools-*.rpm` |
| `.pkg.tar.zst` | `sudo pacman -U ./asus-zenbook-linux-tools-*.pkg.tar.zst` |
| `.AppImage` | `sudo ./asus-zenbook-linux-tools-*-x86_64.AppImage` |
| `.flatpak` | `sudo flatpak install --system ./asus-zenbook-linux-tools-*.flatpak` then |
| | `sudo flatpak run org.github.ventura8.AsusZenBookLinuxTools` |
| `.snap` | `sudo snap install --dangerous ./asus-zenbook-linux-tools_*.snap` (after checksum verify) |

Portable AppImage / Flatpak / Snap installer bundles are also attached; native
packages are recommended for systemd and udev integration.

### Download install.sh and verify integrity (any supported distro)

Both files come from the same GitHub release tag; `sha256sum -c` is an integrity
check that the downloaded script matches its checksum file—not independent or
authenticated verification from a separate trusted channel.

```bash
curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.5/install.sh.sha256 \
  -o install.sh.sha256 &&
  curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.5/install.sh \
  -o install.sh &&
  sha256sum -c install.sh.sha256 &&
  sudo bash ./install.sh
```
