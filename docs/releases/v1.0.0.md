# Release v1.0.0 — Initial Official Release

We are proud to announce the initial official release (**v1.0.0**) of
**ASUS ZenBook Linux Tools**, providing hardware integration, evdev daemons,
audio smart amplifier initialization, and custom touchpad gesture support
for ASUS ZenBook laptops running Linux.

---

## 🌟 Key Features & Improvements

### 🔊 1. Audio Smart Amplifier Fix

- **Cirrus ALC294 Initialization**: Sends hardware verbs via `hda-verb`
  to enable silent internal speakers.
- **Sleep & Suspend Resume Hook**: Automatically re-applies initialization
  verbs upon waking from suspend or sleep via systemd sleep hooks.

### 🖥️ 2. Hardware Hotkey & ScreenPad Daemon (`asus-hotkey-daemon.py`)

- **Dual-Screen Window Swapping**: Monitors `Asus WMI hotkeys` events and
  moves the focused window across monitors via `wmctrl` / `xdotool` (KDE/XFCE/
  LXQt and topology fallbacks), then `Super + Shift + Arrow` via `uinput` on
  GNOME when needed.
- **Hardware Toggles**: Handles ScreenPad backlight toggle, Shift+Fn
  brightness for ScreenPad levels (plain Fn brightness stays on the main
  panel; Alt is avoided because ASUS brightness keys are F4/F5 and Alt+F4
  closes windows on GNOME), fan mode switching (Silent/Balanced/Performance),
  camera privacy toggles, and Display Toggle / XF86Display opening the native
  monitor OSD when possible (sticky Super+P via `ydotool`/`xdotool`, Mutter
  cycle, or DE settings). Stock `F8` stays unbound.
- **Notification ID Overwriting & Thermal Icons**: Persists active D-Bus replacement IDs
  under `/run/asus-zenbook-notif/$UID/` to update popups in place without flooding
  desktop notification stacks, featuring dynamic thermal icons
  (`power-profile-performance`, `power-profile-balanced`, `power-profile-power-saver`).
- **Event Debouncing & Multi-Desktop Settings**: 300 ms daemon event debouncing
  window to prevent kernel WMI double-firing, alongside multi-desktop Control
  Center launcher support (GNOME, KDE Plasma, XFCE, LXQt, Cinnamon, MATE).

### 🖐️ 3. Touchpad Share Gesture Daemon (`asus-touchpad-share.py`)

- **Corner Gesture Recognition**: Detects tap releases on the top-left
  Share icon of capacitive touchpads.
- **Screenshot Triggering**: Invokes `asus-screenshot.sh` (GNOME Shell D-Bus,
  portal, and DE helpers including LXQt `screengrab -r`, Cinnamon
  `gnome-screenshot --area`, MATE `mate-screenshot --area`); `Super + Shift + S` /
  Print keychords are fallback paths only inside that helper.

### ⚙️ 4. Interactive Installer & Uninstaller

- **`install.sh` / `uninstall.sh`**: Terminal wizard providing selective
  feature installation, desktop shortcut configuration for
  GNOME/KDE/XFCE/LXQt/Cinnamon/MATE (screenshot, settings, and XF86Display / Super+p monitor
  OSD — not stock F8; LXQt via `globalkeyshortcuts.conf`), and keybinding
  rollback on uninstallation. Install records newly
  installed OS packages; uninstall removes those packages. With no
  `installed-packages` record, set `ASUS_UNINSTALL_FALLBACK_PKGS=1` to remove
  known project deps only (never base interpreters such as `python3`).

## 🛠️ Testing & Quality Standards

- **Distro Matrix Coverage**: CI/local Docker matrix validates nine always-on
  lanes: Ubuntu 26.04, Debian trixie, Fedora 44, Rocky 9, openSUSE Tumbleweed,
  Arch latest, openSUSE Leap 16.0, AlmaLinux 10, and Manjaro base. SteamOS maps
  to the Arch package family via OS detection (not a dedicated CI image).
  Full-DE family package variants (`ASUS_CI_DE_FAMILY`) run in the same push/PR
  pipeline (`distro-full-de`); not nightly. Coverage thresholds are gated in one
  canonical lane. Cross-distro lanes run
  `--compat-only`, which includes `scripts/run_distro_install_smoke.sh` (DESTDIR
  install/uninstall, package probes including PyGObject, helper syntax/imports,
  DE family checks, DESKTOP gnome/kde/xfce/lxqt/cinnamon/mate configure cycles with stubs, and
  an
  in-container live package cycle that purges sentinel deps then runs
  install/uninstall with `SKIP_PKG_*=0`). Coverage-gate (`--tests-only`) skips
  that smoke and only runs unit/kcov/e2e/Python coverage. Rocky/RHEL/Alma smoke does
  not require unpackaged `alsa-tools`/`ydotool` (Fedora still probes both);
  SOUND uses bundled `asus_hda_verb.py` when `hda-verb` is absent.
  Coverage-gate uses the shared `docker/images/tests/ubuntu-26.04.Dockerfile`
  image.
- **Fast Mocked E2E Timeout Policy**: Each mocked/CI E2E test command is
  bounded to a 20-30 second timeout budget. Timeout overruns fail tests by
  design.

- **Strict Linting**: Clean compliance with `ruff`, `pylint` (10.00/10),
  `yamllint`, `markdownlint`, plus shell scripts passing both `bash -n` and
  `shellcheck`.
- **High Code Coverage**:
  - Python coverage: at least **90%** on product modules
    (`bin/*.py`, `tools/*.py`, `shared_imports.py`, `scripts/check_file_size_limits.py`,
    `sitecustomize.py`) enforced with
    `coverage report --include="bin/*.py,tools/*.py,shared_imports.py,scripts/check_file_size_limits.py,sitecustomize.py" --fail-under=90`.
  - Shell coverage: at least **90%** on product Bash
    (`bin/*.sh`, `lib/*.sh`, `install.sh`, `uninstall.sh`) enforced with `kcov` line coverage
    checks.
- **Modular Test Architecture**: Separated unit tests (`tests/unit/`) and
  end-to-end tests with explicit mocked (`tests/e2e/mock/`) and real-system
  (`tests/e2e/real/`) suites.
- **CI & Local Pipeline**: Integrated GitHub Actions CI with step summaries
  for Radon complexity and coverage, alongside canonical local scripts
  (`./scripts/build-and-test.sh` and opt-in `./scripts/run_real_e2e.sh`).

## 📦 Installation Quick-Start

### Ubuntu PPA (resolute)

```bash
sudo add-apt-repository ppa:ventura8/asus-zenbook-linux-tools &&
  sudo apt update &&
  sudo apt install asus-zenbook-linux-tools
```

Apt install runs the interactive component wizard. Reconfigure with
`sudo dpkg-reconfigure asus-zenbook-linux-tools` or
`sudo asus-zenbook-configure`.

### curl | bash (any supported distro)

```bash
curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.0/install.sh |
  sudo bash
```
