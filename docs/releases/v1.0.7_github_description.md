# ASUS ZenBook Linux Tools v1.0.7 - SonarQube Cloud Analysis and Code-Quality Fixes

**ASUS ZenBook Linux Tools v1.0.7** puts the project under continuous SonarQube
Cloud analysis, feeds it the coverage the pipeline already produces, and fixes
everything that first analysis surfaced.

---

## 🔬 SonarQube Cloud analysis in CI

* New `sonarqube` job after `coverage-merge`: full-history checkout for new-code
  attribution, `sonar.projectVersion` from `VERSION`, skipped on fork PRs, and
  still analysing when a coverage gate fails.
* **Real coverage**: Python coverage XML plus a new kcov Cobertura → SonarQube
  generic coverage converter (`sonar.coverageReportPaths` accepts only the
  generic format, never Cobertura). Both writers are best-effort so a report
  failure cannot turn a passing gate red.
* Converter hardening: reads and writes confined to caller-named roots, internal
  entity declarations rejected (billion laughs) without a new dependency, the
  report's declared encoding honoured, and stale reports removed on refusal.

## 🛠️ Product fixes from the first analysis

* **GNOME window swap**: monitor scale compared with `math.isclose` instead of
  float equality, so a fractional-scale monitor is no longer skipped or matched
  by accident.
* **Touchpad Share**: read-loop failures log a traceback before re-raising.
* Redundant exception classes, duplicated literals, `\d` classes,
  `set.update()`, an optional chain in the GNOME extension, and two
  super-linear regexes in the catalog linter.

## 🧪 Verification

* 13 focused converter unit tests plus parity tests pinning every Sonar report
  path and the CI job wiring.
* Quality gate on the release commit: **0 new issues, 0 security hotspots,
  90.0% coverage on new code**.

## 📦 Dependency updates bundled with this release

All nine pinned Docker base image digests refreshed (seven had moved) and
`docker/setup-buildx-action` 4.3.0→4.4.1. Python and npm pins were already at
their latest releases. See
[v1.0.7.md](https://github.com/ventura8/asus-zenbook-linux-tools/blob/v1.0.7/docs/releases/v1.0.7.md).

## 📥 Installation

### Ubuntu PPA (resolute)

```bash
sudo add-apt-repository ppa:ventura8/asus-zenbook-linux-tools &&
  sudo apt update &&
  sudo apt install asus-zenbook-linux-tools
```

### GitHub Release packages

Download **`SHA256SUMS`** and your release asset from the
[v1.0.7 release assets](https://github.com/ventura8/asus-zenbook-linux-tools/releases/tag/v1.0.7),
then verify the downloaded asset before install:

```bash
grep -F 'your-asset-filename' SHA256SUMS | sha256sum -c -
```

| Asset | Install (after checksum verify) |
| --- | --- |
| `.deb` | `sudo apt install ./asus-zenbook-linux-tools_*.deb` |
| `.rpm` (Fedora/Rocky/Alma) | `sudo dnf install ./asus-zenbook-linux-tools-*.rpm` |
| `.rpm` (openSUSE) | `sudo zypper install --allow-unsigned-rpm ./asus-zenbook-linux-tools-*.rpm` |
| `.pkg.tar.zst` | `sudo pacman -U ./asus-zenbook-linux-tools-*.pkg.tar.zst` |
| `.AppImage` | `sudo ./asus-zenbook-linux-tools-*-x86_64.AppImage` |
| `.flatpak` | `sudo flatpak install --system ./asus-zenbook-linux-tools-*.flatpak` then |
| | `sudo flatpak run org.github.ventura8.AsusZenBookLinuxTools` |
| `.snap` | `sudo snap install --dangerous ./asus-zenbook-linux-tools_*.snap` (after checksum verify) |

Portable AppImage / Flatpak / Snap installer bundles are also attached; native
packages are recommended for systemd and udev integration.

### Download install.sh and verify integrity (any supported distro)

Both files come from the same GitHub release tag; `sha256sum -c` is an integrity
check that the downloaded script matches its checksum file—not independent or
authenticated verification from a separate trusted channel.

```bash
curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.7/install.sh.sha256 \
  -o install.sh.sha256 &&
  curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.7/install.sh \
  -o install.sh &&
  sha256sum -c install.sh.sha256 &&
  sudo bash ./install.sh
```
