# ASUS ZenBook Linux Tools v1.0.8 - Security Hardening from SonarQube Analysis

**ASUS ZenBook Linux Tools v1.0.8** closes the security findings SonarQube Cloud
raised against the project, including a real path-traversal hole in the root
HD-audio helper.

---

## 🔒 Root HD-audio helper confines its device path

* `bin/asus_hda_verb.py` runs as root and took its hwdep path from `argv`.
  `validated_device()` now requires that path to resolve inside `/dev/snd`
  (`DEV_SND_ROOT` for fixtures) and to name an `hwC<N>D<M>` node; anything else
  exits 1 before a file is opened. Four unit tests cover it.

## 🧱 Build and CI supply-chain hygiene

* Coverage installed as `coverage==7.16.1 --only-binary :all:` (pinned, no source
  builds, no setup scripts).
* `npm ci` / `npm install -g` use `--ignore-scripts`.
* `curl --proto '=https' --tlsv1.2` for the NodeSource key, hadolint, kcov
  tarballs and the xfconf tarball, so redirects cannot downgrade to HTTP.
* The loginctl test stub is written owner-only.

## 🔬 SonarQube project

* Project renamed to `asus-zenbook-linux-tools`, bound to the GitHub repo, with
  automatic analysis disabled so the CI scan (which carries coverage) is the
  single source of truth.

## 📦 Dependency updates bundled with this release

`pylint` 4.0.8→4.0.9; all other Python/npm pins, GitHub Action pins and Docker
base digests were already current.

## 🧪 Verification

792 unit tests plus 51 subtests pass; both lint waves green (pylint 10.00/10,
shellcheck, hadolint, radon rank A).

## 📥 Installation

### Ubuntu PPA (resolute)

```bash
sudo add-apt-repository ppa:ventura8/asus-zenbook-linux-tools &&
  sudo apt update &&
  sudo apt install asus-zenbook-linux-tools
```

### GitHub Release packages

Download **`SHA256SUMS`** and your release asset from the
[v1.0.8 release assets](https://github.com/ventura8/asus-zenbook-linux-tools/releases/tag/v1.0.8),
then verify the downloaded asset before install:

```bash
grep -F 'your-asset-filename' SHA256SUMS | sha256sum -c -
```

| Asset | Install (after checksum verify) |
| --- | --- |
| `.deb` | `sudo apt install ./asus-zenbook-linux-tools_*.deb` |
| `.rpm` (Fedora/Rocky/Alma) | `sudo dnf install ./asus-zenbook-linux-tools-*.rpm` |
| `.rpm` (openSUSE) | `sudo zypper install --allow-unsigned-rpm ./asus-zenbook-linux-tools-*.rpm` |
| `.pkg.tar.zst` | `sudo pacman -U ./asus-zenbook-linux-tools-*.pkg.tar.zst` |
| `.AppImage` | `sudo ./asus-zenbook-linux-tools-*-x86_64.AppImage` |
| `.flatpak` | `sudo flatpak install --system ./asus-zenbook-linux-tools-*.flatpak` then |
| | `sudo flatpak run org.github.ventura8.AsusZenBookLinuxTools` |
| `.snap` | `sudo snap install --dangerous ./asus-zenbook-linux-tools_*.snap` (after checksum verify) |

Portable AppImage / Flatpak / Snap installer bundles are also attached; native
packages are recommended for systemd and udev integration.

### Download install.sh and verify integrity (any supported distro)

Both files come from the same GitHub release tag; `sha256sum -c` is an integrity
check that the downloaded script matches its checksum file—not independent or
authenticated verification from a separate trusted channel.

```bash
curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.8/install.sh.sha256 \
  -o install.sh.sha256 &&
  curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.8/install.sh \
  -o install.sh &&
  sha256sum -c install.sh.sha256 &&
  sudo bash ./install.sh
```
