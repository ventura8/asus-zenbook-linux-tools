# Release v1.0.7 — SonarQube Cloud Analysis and Code-Quality Fixes

**ASUS ZenBook Linux Tools v1.0.7** puts the project under continuous
SonarQube Cloud analysis, feeds it the coverage the pipeline already produces,
and fixes everything that first analysis surfaced — including a real
float-comparison defect in the GNOME window-swap monitor lookup.

---

## 🌟 Key Features & Improvements

### 🔬 SonarQube Cloud analysis in CI

- **New `sonarqube` job** in [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml),
  running after `coverage-merge` with a full-history checkout (new-code
  attribution), `sonar.projectVersion` from the root `VERSION`, and
  `secrets.SONAR_TOKEN`. It is skipped on fork PRs, where the token is not
  exposed, and still analyses when a coverage gate fails so findings stay
  visible.
- **Real coverage, not 0%**: the merge step writes
  `reports/coverage/merged/coverage.xml` (Python) and, through the new
  [`scripts/coverage/cobertura_to_sonar_generic.py`](../../scripts/coverage/cobertura_to_sonar_generic.py),
  `reports/coverage/merged/shell-coverage.xml` (shell). `sonar.coverageReportPaths`
  accepts **only** SonarQube's generic coverage XML — never Cobertura — so kcov's
  report is converted before it is handed over. Both writers are best-effort: a
  report failure can never turn a passing gate into a red pipeline.
- **[`sonar-project.properties`](../../sonar-project.properties)**: project and
  organization keys, `sources` vs `tests`, and exclusions for generated,
  vendored, and packaging payload trees.
- **Converter hardening**: reads and writes are confined to caller-named roots
  (`--source-base` / `--base`), documents declaring internal entities are
  rejected (billion-laughs and quadratic-blowup inputs) without adding a runtime
  dependency, the report's own encoding declaration is honoured so non-ASCII
  paths survive, and a refused or empty conversion removes any stale report
  instead of leaving one for Sonar to read as current coverage.

### 🛠️ Product fixes from the first analysis

- **GNOME window swap**: monitor scale is compared with `math.isclose` instead
  of float equality in `_monitor_index_for_scale`, so a fractional-scale monitor
  can no longer be skipped or matched by accident.
- **Touchpad Share**: the read-loop handler logs a traceback
  (`logging.exception`) before re-raising, so a device loss is diagnosable from
  the journal.
- **Maintainability**: redundant exception classes removed
  (`json.JSONDecodeError` under `ValueError`, `FileNotFoundError` under
  `OSError`), duplicated literals extracted to constants (control-center script
  name, invalid-mode message, topology-unavailable warning, `'all'`/`'none'`
  tokens), concise `\d` character classes, `set.update()` in place of an
  `add()` loop, and an optional chain in the GNOME extension's monitor guard.
- **Regex safety**: the printf-specifier and translation-artifact patterns in
  `check_catalog_quality.py` no longer backtrack super-linearly (possessive
  quantifiers and a bounded whitespace class); every printf form was re-verified
  against the new pattern.

### 🧪 Verification

- 13 focused unit tests for the coverage converter
  (`tests/unit/scripts/test_cobertura_to_sonar_generic.py`): conversion output,
  duplicate-class line merging, dropped entries, entity refusal, empty report,

- `tests/unit/shell/test_pipeline_ci_parity.py` pins the Sonar report paths, the

  plumbing cannot regress silently.
- SonarQube quality gate on the merge commit: **0 new issues, 0 security

## 📦 Installation Quick-Start

### Ubuntu PPA (resolute)

```bash
sudo add-apt-repository ppa:ventura8/asus-zenbook-linux-tools &&
  sudo apt update &&
  sudo apt install asus-zenbook-linux-tools
```

### GitHub Release packages (all supported families)

Download assets and **`SHA256SUMS`** from the
[v1.0.7 GitHub Release](https://github.com/ventura8/asus-zenbook-linux-tools/releases/tag/v1.0.7).
Verify the downloaded asset before installation:

```bash
grep -F 'your-asset-filename' SHA256SUMS | sha256sum -c -
```

| Asset | Install (after checksum verify) |
| --- | --- |
| `.deb` | `sudo apt install ./asus-zenbook-linux-tools_*.deb` |
| `.rpm` (Fedora/Rocky/Alma) | `sudo dnf install ./asus-zenbook-linux-tools-*.rpm` |
| `.rpm` (openSUSE) | `sudo zypper install --allow-unsigned-rpm ./asus-zenbook-linux-tools-*.rpm` |
| `.pkg.tar.zst` | `sudo pacman -U ./asus-zenbook-linux-tools-*.pkg.tar.zst` |
| `.AppImage` | `sudo ./asus-zenbook-linux-tools-*-x86_64.AppImage` |
| `.flatpak` | `sudo flatpak install --system ./asus-zenbook-linux-tools-*.flatpak` then |
| | `sudo flatpak run org.github.ventura8.AsusZenBookLinuxTools` |
| `.snap` | `sudo snap install --dangerous ./asus-zenbook-linux-tools_*.snap` (after checksum verify) |

Reconfigure after any native package install: `sudo asus-zenbook-configure`.

### Download install.sh, verify checksum, and run with sudo bash (any supported distro)

```bash
curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.7/install.sh.sha256 \
  -o install.sh.sha256 &&
  curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.7/install.sh \
  -o install.sh &&
  sha256sum -c install.sh.sha256 &&
  sudo bash ./install.sh
```

Both files come from the same GitHub release tag; `sha256sum -c` is an integrity
check that the downloaded script matches its checksum file—not independent or
authenticated verification from a separate trusted channel.
