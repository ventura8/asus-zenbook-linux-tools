# Release v1.0.5 — LXQt Configure Privilege-Escalation Fix

**ASUS ZenBook Linux Tools v1.0.5** is a security release that closes a local
privilege-escalation path in the LXQt desktop configure step, where root
previously followed a user-controlled symlink under `~/.config` while
chmod'ing/chown'ing and writing shortcut state.

---

## 🌟 Key Features & Improvements

### 🛡️ LXQt configure privilege-escalation fix

- **Root no longer touches user-controlled paths directly**: [`lib/install-lxqt.sh`](../../lib/install-lxqt.sh)
  `_lxqt_ensure_conf_dir` and `_lxqt_atomic_write_conf` now perform `mkdir`,
  `chmod`, and the config write **as the target LXQt session user** via
  `_install_run_as_user`, the same privilege-drop pattern already used for
  GNOME extension installs, instead of running those operations as root.
- **Symlink rejection as defense-in-depth**: Explicit `[ -L ... ]` checks now
  refuse to operate on `~/.config`, `~/.config/lxqt`, or
  `globalkeyshortcuts.conf` when any of those paths is a symlink, even in the
  non-root code path.
- **Removed the vulnerable helper**: `_lxqt_chown_path`, which ran
  `chown "$user:" "$path"` as root without `--no-dereference`, is no longer
  needed and has been removed.

**Impact of the fixed issue**: an unprivileged local user with an active LXQt
session could previously replace `~/.config` (or `~/.config/lxqt`) with a
symlink to a privileged directory (for example `/etc`) before an administrator
ran `sudo ./install.sh` / `sudo asus-zenbook-configure` with the LXQt desktop
component. Root's subsequent `chmod 0700` + `chown` followed the symlink,
handing that user ownership of the privileged target. Configure now drops to
the session user before any of those filesystem operations, so this path no
longer allows escalation.

### 🧪 Verification

- Existing mocked LXQt E2E suite (`tests/e2e/mock/test_install_de_lxqt.py`)
  passes unchanged against the hardened implementation.
- `bash -n` syntax check and `shellcheck` pass on `lib/install-lxqt.sh` (only
  pre-existing informational `SC2016` notices on intentionally single-quoted
  privilege-drop scripts).
- New `_run_lxqt_root_branch_paths` coverage-driver regression cases
  ([`scripts/coverage/drivers/lxqt_helpers.sh`](../../scripts/coverage/drivers/lxqt_helpers.sh))
  fake root (`id -u` → `0`) to exercise the `_install_run_as_user` root
  branches directly and assert: normal creation/writes still succeed, a
  symlinked `~/.config`, `~/.config/lxqt`, or conf-file destination is
  rejected without touching the real target's permissions or contents, and no
  stray temp files are left behind on rejection.

## 📦 Installation Quick-Start

### Ubuntu PPA (resolute)

```bash
sudo add-apt-repository ppa:ventura8/asus-zenbook-linux-tools &&
  sudo apt update &&
  sudo apt install asus-zenbook-linux-tools
```

### GitHub Release packages (all supported families)

Download assets and **`SHA256SUMS`** from the
[v1.0.5 GitHub Release](https://github.com/ventura8/asus-zenbook-linux-tools/releases/tag/v1.0.5).
Verify the downloaded asset before installation:

```bash
grep -F 'your-asset-filename' SHA256SUMS | sha256sum -c -
```

| Asset | Install (after checksum verify) |
| --- | --- |
| `.deb` | `sudo apt install ./asus-zenbook-linux-tools_*.deb` |
| `.rpm` (Fedora/Rocky/Alma) | `sudo dnf install ./asus-zenbook-linux-tools-*.rpm` |
| `.rpm` (openSUSE) | `sudo zypper install --allow-unsigned-rpm ./asus-zenbook-linux-tools-*.rpm` |
| `.pkg.tar.zst` | `sudo pacman -U ./asus-zenbook-linux-tools-*.pkg.tar.zst` |
| `.AppImage` | `sudo ./asus-zenbook-linux-tools-*-x86_64.AppImage` |
| `.flatpak` | `sudo flatpak install --system ./asus-zenbook-linux-tools-*.flatpak` then |
| | `sudo flatpak run org.github.ventura8.AsusZenBookLinuxTools` |
| `.snap` | `sudo snap install --dangerous ./asus-zenbook-linux-tools_*.snap` (after checksum verify) |

Reconfigure after any native package install: `sudo asus-zenbook-configure`.

### Download install.sh, verify checksum, and run with sudo bash (any supported distro)

```bash
curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.5/install.sh.sha256 \
  -o install.sh.sha256 &&
  curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.5/install.sh \
  -o install.sh &&
  sha256sum -c install.sh.sha256 &&
  sudo bash ./install.sh
```

Both files come from the same GitHub release tag; `sha256sum -c` is an integrity
check that the downloaded script matches its checksum file—not independent or
authenticated verification from a separate trusted channel.
