# ASUS ZenBook Linux Tools v1.0.6 - ScreenPad Brightness Persists Across Reboot

**ASUS ZenBook Linux Tools v1.0.6** fixes the ScreenPad backlight coming up
nearly dark after every boot: the level set with Shift+Fn brightness is now
re-applied at startup.

---

## 💡 ScreenPad brightness restored at boot

* **Root cause**: the panel is already off at shutdown, so
  `systemd-backlight@backlight:asus_screenpad.service` saved `0` and clamped it
  to a dim floor (12/255) at boot—*"Saved brightness 0 is too low; increasing
  to 12"*. The hotkey helper persisted the real level under
  `/var/lib/asus-zenbook-linux-tools/<uid>/screenpad_brightness`, but nothing
  re-applied it at boot.
* **New `asus-screenpad-brightness.sh restore`**: loads the persisted level
  (session user's file, else the newest per-user file since no session exists
  at boot), clamps to `max_brightness`, writes with read-back verify, no OSD;
  exit 0 / no-op when nothing was saved.
* **Unit wiring**: `asus-hotkey-daemon.service` gains
  `ExecStartPre=-/usr/local/bin/asus-screenpad-brightness.sh restore` and
  `After=systemd-backlight@backlight:asus_screenpad.service`, so the persisted
  level wins over systemd-backlight's clamp.
* Main panel (`intel_backlight`) was already restored correctly—unchanged.

## 🧪 Verification

* New unit tests: newest-state-file pick with no session user, clamp to max,
  and no-state no-op; installer unit-text test asserts the `ExecStartPre` line.
* `shellcheck`, `pylint` 10.00/10, `systemd-analyze verify` clean.

## 📥 Installation

### Ubuntu PPA (resolute)

```bash
sudo add-apt-repository ppa:ventura8/asus-zenbook-linux-tools &&
  sudo apt update &&
  sudo apt install asus-zenbook-linux-tools
```

### GitHub Release packages

Download **`SHA256SUMS`** and your release asset from the
[v1.0.6 release assets](https://github.com/ventura8/asus-zenbook-linux-tools/releases/tag/v1.0.6),
then verify the downloaded asset before install:

```bash
grep -F 'your-asset-filename' SHA256SUMS | sha256sum -c -
```

| Asset | Install (after checksum verify) |
| --- | --- |
| `.deb` | `sudo apt install ./asus-zenbook-linux-tools_*.deb` |
| `.rpm` (Fedora/Rocky/Alma) | `sudo dnf install ./asus-zenbook-linux-tools-*.rpm` |
| `.rpm` (openSUSE) | `sudo zypper install --allow-unsigned-rpm ./asus-zenbook-linux-tools-*.rpm` |
| `.pkg.tar.zst` | `sudo pacman -U ./asus-zenbook-linux-tools-*.pkg.tar.zst` |
| `.AppImage` | `sudo ./asus-zenbook-linux-tools-*-x86_64.AppImage` |
| `.flatpak` | `sudo flatpak install --system ./asus-zenbook-linux-tools-*.flatpak` then |
| | `sudo flatpak run org.github.ventura8.AsusZenBookLinuxTools` |
| `.snap` | `sudo snap install --dangerous ./asus-zenbook-linux-tools_*.snap` (after checksum verify) |

Portable AppImage / Flatpak / Snap installer bundles are also attached; native
packages are recommended for systemd and udev integration.

### Download install.sh and verify integrity (any supported distro)

Both files come from the same GitHub release tag; `sha256sum -c` is an integrity
check that the downloaded script matches its checksum file—not independent or
authenticated verification from a separate trusted channel.

```bash
curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.6/install.sh.sha256 \
  -o install.sh.sha256 &&
  curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.6/install.sh \
  -o install.sh &&
  sha256sum -c install.sh.sha256 &&
  sudo bash ./install.sh
```
