# Release v1.0.3 — Multi-distro Release Packaging

**ASUS ZenBook Linux Tools v1.0.3** ships native packages for every CI-supported
distro family on GitHub Releases—`.deb` (PPA unchanged), Fedora/Rocky/openSUSE
`.rpm`, Arch `.pkg.tar.zst`, plus experimental AppImage/Flatpak/Snap installer
bundles—using one shared payload stager so packaging cannot drift from Debian.

---

## 🌟 Key Features & Improvements

### 📦 Shared payload staging

- [`packaging/stage-payload.sh`](../../packaging/stage-payload.sh) copies product
  files, compiles all 99 gettext catalogs, and installs
  `/usr/sbin/asus-zenbook-configure` for every native format.
- [`debian/rules`](../../debian/rules) delegates to the same script so PPA `.deb`
  builds stay the source of truth without duplicate copy lists.

### 🐧 Native packages per distro family

- **RPM** ([`packaging/rpm/asus-zenbook-linux-tools.spec`](../../packaging/rpm/asus-zenbook-linux-tools.spec)):
  `noarch` spec with Fedora / EL10 / openSUSE conditional `Requires` and
  `%post`/`%preun`/`%postun` scriptlets mirroring Debian `postinst`/`prerm`.
- **Arch** ([`packaging/arch/PKGBUILD`](../../packaging/arch/PKGBUILD) +
  [`.install`](../../packaging/arch/asus-zenbook-linux-tools.install)): pacman hooks
  share [`packaging/scriptlets/configure-common.sh`](../../packaging/scriptlets/configure-common.sh).

### 🚀 Tag workflow & CI

- [`.github/workflows/ppa-release.yml`](../../.github/workflows/ppa-release.yml):
  `build-packages` matrix builds RPM (Fedora 44, Rocky 10, openSUSE Tumbleweed),
  Arch, AppImage, Flatpak, and classic Snap; `github-release` attaches every
  artifact alongside the unsigned `.deb`.
- [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml): `package-smoke` matrix builds
  all seven package targets via [`scripts/build_release_package.sh`](../../scripts/build_release_package.sh).
- Local `--full` runs Docker-native RPM/Arch and portable AppImage/Flatpak/Snap
  release smoke workers in parallel via
  [`scripts/run_release_package_smoke.sh`](../../scripts/run_release_package_smoke.sh).

### 🧪 Portable installer bundles (experimental)

- **AppImage**, **Flatpak**, and **Snap** ship as **installer-only** bundles—they
  invoke `asus-zenbook-configure` with a bundled payload and still require root
  for systemd/udev/evdev deployment. Native packages remain recommended.

## 📦 Installation Quick-Start

### Ubuntu PPA (resolute)

```bash
sudo add-apt-repository ppa:ventura8/asus-zenbook-linux-tools &&
  sudo apt update &&
  sudo apt install asus-zenbook-linux-tools
```

### GitHub Release packages (all supported families)

Download assets and **`SHA256SUMS`** from the
[v1.0.3 GitHub Release](https://github.com/ventura8/asus-zenbook-linux-tools/releases/tag/v1.0.3).
Verify the downloaded asset before installation:

```bash
grep -F 'your-asset-filename' SHA256SUMS | sha256sum -c -
```

| Asset | Install (after checksum verify) |
| --- | --- |
| `.deb` | `sudo apt install ./asus-zenbook-linux-tools_*.deb` |
| `.rpm` (Fedora/Rocky) | `sudo dnf install ./asus-zenbook-linux-tools-*.rpm` |
| `.rpm` (openSUSE) | `sudo zypper install --allow-unsigned-rpm ./asus-zenbook-linux-tools-*.rpm` |
| `.pkg.tar.zst` | `sudo pacman -U ./asus-zenbook-linux-tools-*.pkg.tar.zst` |
| `.AppImage` | `sudo ./asus-zenbook-linux-tools-*-x86_64.AppImage` |
| `.flatpak` | `sudo flatpak install --system ./asus-zenbook-linux-tools-*.flatpak` then |
| | `sudo flatpak run org.github.ventura8.AsusZenBookLinuxTools` |
| `.snap` | `sudo snap install --dangerous ./asus-zenbook-linux-tools_*.snap` (after checksum verify) |

Reconfigure after any native package install: `sudo asus-zenbook-configure`.

### Download install.sh, verify checksum, and run with sudo bash (any supported distro)

```bash
curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.3/install.sh.sha256 \
  -o install.sh.sha256 &&
  curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.3/install.sh \
  -o install.sh &&
  sha256sum -c install.sh.sha256 &&
  sudo bash ./install.sh
```

Both files come from the same GitHub release tag; `sha256sum -c` is an integrity
check that the downloaded script matches its checksum file—not independent or
authenticated verification from a separate trusted channel.
