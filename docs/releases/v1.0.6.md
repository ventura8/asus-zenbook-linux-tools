# Release v1.0.6 — ScreenPad Brightness Persists Across Reboot

**ASUS ZenBook Linux Tools v1.0.6** fixes the ScreenPad backlight coming up
nearly dark after every boot. The level chosen with Shift+Fn brightness was
already being persisted, but nothing re-applied it at boot, and systemd's own
backlight restore actively worked against it.

---

## 🌟 Key Features & Improvements

### 💡 ScreenPad brightness restored at boot

- **Root cause**: at shutdown the ScreenPad panel is already powered off, so
  `systemd-backlight@backlight:asus_screenpad.service` saves the node as `0`
  and, at boot, logs *"Saved brightness 0 is too low; increasing to 12"*—a
  dim floor (12/255) on every start. The hotkey helper persisted the real level
  to `/var/lib/asus-zenbook-linux-tools/<uid>/screenpad_brightness`, but only
  the toggle-on path and Mutter layout restore ever read it back.
- **New `restore` command** in [`bin/asus-screenpad-brightness.sh`](../../bin/asus-screenpad-brightness.sh):
  loads the persisted level, clamps to `max_brightness`, writes with sysfs
  read-back verify, and stays silent (no OSD / notification). Exits `0` when
  nothing has been persisted yet, leaving the node untouched.
- **Boot-time state lookup without a session user**:
  `_load_screenpad_brightness_any_user` in [`lib/asus-screenpad.sh`](../../lib/asus-screenpad.sh)
  prefers the resolved session user's file and falls back to the newest
  `$STATE_DIR/*/screenpad_brightness` by mtime, because at boot no session
  user exists yet and the per-uid lookup would otherwise land on uid 0.
- **Unit wiring** in [`systemd/asus-hotkey-daemon.service`](../../systemd/asus-hotkey-daemon.service):
  `ExecStartPre=-/usr/local/bin/asus-screenpad-brightness.sh restore`
  (best-effort `-` so a missing node never blocks the hotkey daemon) plus
  `After=systemd-backlight@backlight:asus_screenpad.service` so the persisted
  hotkey level is applied after systemd-backlight's dim clamp and wins.
- **Main panel unaffected**: `intel_backlight` is already saved/restored
  correctly by `systemd-backlight@`; no change there.

### 🧪 Verification

- New unit tests in `tests/unit/shell/test_asus_screenpad_brightness.py`:
  `restore` picks the newest per-user state file with no session user,
  clamps an out-of-range persisted value to `max_brightness`, and is a no-op
  (exit 0) without state. `tests/unit/shell/test_install.py` asserts the
  deployed unit carries the `ExecStartPre` restore line.
- `shellcheck`/`bash -n` clean on the touched scripts; `pylint` 10.00/10 on

## 📦 Installation Quick-Start

### Ubuntu PPA (resolute)

```bash
sudo add-apt-repository ppa:ventura8/asus-zenbook-linux-tools &&
  sudo apt update &&
  sudo apt install asus-zenbook-linux-tools
```

### GitHub Release packages (all supported families)

Download assets and **`SHA256SUMS`** from the
[v1.0.6 GitHub Release](https://github.com/ventura8/asus-zenbook-linux-tools/releases/tag/v1.0.6).
Verify the downloaded asset before installation:

```bash
grep -F 'your-asset-filename' SHA256SUMS | sha256sum -c -
```

| Asset | Install (after checksum verify) |
| --- | --- |
| `.deb` | `sudo apt install ./asus-zenbook-linux-tools_*.deb` |
| `.rpm` (Fedora/Rocky/Alma) | `sudo dnf install ./asus-zenbook-linux-tools-*.rpm` |
| `.rpm` (openSUSE) | `sudo zypper install --allow-unsigned-rpm ./asus-zenbook-linux-tools-*.rpm` |
| `.pkg.tar.zst` | `sudo pacman -U ./asus-zenbook-linux-tools-*.pkg.tar.zst` |
| `.AppImage` | `sudo ./asus-zenbook-linux-tools-*-x86_64.AppImage` |
| `.flatpak` | `sudo flatpak install --system ./asus-zenbook-linux-tools-*.flatpak` then |
| | `sudo flatpak run org.github.ventura8.AsusZenBookLinuxTools` |
| `.snap` | `sudo snap install --dangerous ./asus-zenbook-linux-tools_*.snap` (after checksum verify) |

Reconfigure after any native package install: `sudo asus-zenbook-configure`.

### Download install.sh, verify checksum, and run with sudo bash (any supported distro)

```bash
curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.6/install.sh.sha256 \
  -o install.sh.sha256 &&
  curl -fsSL \
  https://raw.githubusercontent.com/ventura8/asus-zenbook-linux-tools/v1.0.6/install.sh \
  -o install.sh &&
  sha256sum -c install.sh.sha256 &&
  sudo bash ./install.sh
```

Both files come from the same GitHub release tag; `sha256sum -c` is an integrity
check that the downloaded script matches its checksum file—not independent or
authenticated verification from a separate trusted channel.
